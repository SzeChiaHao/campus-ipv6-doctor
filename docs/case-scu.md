# 实测案例：四川大学 江安校区 西园八舍

2026-11 实测。地理与运营商信息仅供定位，重点是**数据形态**。

## 结论

| 项目 | 值 |
|---|---|
| 接入点 | 宿舍墙上网口（有线，1 Gbps 链路） |
| 认证 | **免认证**，插上直接拿公网地址 |
| IPv4 | `121.48.199.149/24`，网关 `121.48.199.254`（CERNET 教育网公网段） |
| IPv6 前缀 | **`2001:250:2003:8f9f::/64`** |
| IPv6 地址来源 | `RouterAdvertisement`（SLAAC） |
| IPv6 默认路由 | `::/0 via fe80::7608:aaff:fe99:5c16` |
| 地址有效期 | Public 29 天 / Temporary 6 天 |
| ICMP 出口 | `2400:3200::1`、`240c::6666` 均通 |
| HTTP 出口 | `https://ipv6.baidu.com/` 通 |
| 谷歌 IPv6 | 不通（CERNET 2019-10 起屏蔽） |
| 前缀委派（PD） | **未观察到**（RA 直发 /64；Windows 不做 PD 客户端，无法进一步验证） |

## 踩的两个坑

### 坑 1：以太网网卡的 IPv6 绑定是关的

同一根网线、同一台机器：

```
Get-NetAdapterBinding -ComponentID ms_tcpip6
  以太网   False        ← 罪魁
  WLAN     True
```

而 `DisabledComponents = 0`，全局策略完全正常。表现：

- `netsh interface ipv6 show addresses` 里**没有"以太网"这个接口**
- `netsh interface ipv6 show route` 里没有 `::/0`
- 看起来就像"学校没给 IPv6"

打开绑定后立刻拿到地址。**这就是本项目的 L1 判定为什么必须存在。**

### 坑 2：无线和有线同时在线时走的是无线

同一台机器连着 `SCUNET`（校园无线）测，只有 `fe80::`，判断"没有 IPv6"。实际是流量全走无线，而那个 AP 确实没有 IPv6（另一个物理链路问题）。

测有线前必须 `netsh wlan disconnect`。

## 无线的对照数据

同一位置、同一台机器，连无线 `SCUNET`（5 GHz 802.11ax，需 web 认证）：

```
IPv4  10.134.61.147/21，网关 10.134.63.254     ← 内网段，有认证网关
IPv6  仅 fe80::，无 ::/0
ICMPv6 2400:3200::1 不通
```

**同一个人、同一间宿舍：有线口有 IPv6，无线 AP 没有。** 这说明"判断一个学校有没有 IPv6"必须精确到**具体哪个接入点**，不能按学校或楼栋下结论。

## 上游只有 SLAAC /64 没有 PD 的后果

RA 直接下发一整段 `/64`，没有 DHCPv6-PD。这意味着：

> 原厂家用路由器无法把 IPv6 分给局域网设备。

实测一台水星 MW325R（原厂固件）接在这个口上：

```
str.js（31837 字节界面文案）里 ipv6 出现 0 次
menu.js 完整菜单树 24 项，无任何 IPv6 入口
LAN 侧 ping -6 fe80::1 / fe80::2 均无回应，无 RA
```

即**连路由器自身都没有 IPv6 代码**，不是"配错了"。

⚠️ 顺带更正一个常见误解：这台机器的 WiFi SSID 叫 `MERCURY_26A3`，而 `26A3` 是 **BSSID `4c:b7:e0:fc:26:a3` 的末四位**，不是型号。真实型号要从 `http://192.168.1.1/` 返回页面的 `<title>` 里读（这里是 `MW325R`）。

## 复现方法

```powershell
# 1. 插网线，关无线
netsh wlan disconnect

# 2. 体检
powershell -NoProfile -ExecutionPolicy Bypass -File windows\ipv6-doctor.ps1

# 3. 若是 L1 判定失败，修复后重测
windows\ipv6-doctor-fix.bat
```

## 二层 AP 方案：不刷机，让全屋拿到 IPv6（已实测成功）

### 背景

这台墙上网口分配的是 CERNET 公网段（`121.48.199.0/24`），**不需要 MAC 绑定式的认证**，因此"桥接"方案的最大障碍不存在。

> 常见教程会把"桥接"否掉，理由是"需要认证的校园网桥接后透传不过认证"。**这个理由只对认证网成立**。判断方法：看设备直接插网口拿到的 IPv4 是 `10.x`/`172.16-31.x` 内网段（要认证），还是 CERNET 公网段（多半免认证）。

### 做法

把路由器降级成二层设备（AP + 交换机），不做任何路由：

1. 关闭路由器 DHCP 服务器（**必须**，否则和上游 DHCP 在同一广播域抢答）
2. WDS / 无线桥接保持关闭
3. 上游网线接路由器的 **LAN 口**，**WAN 口空着**
4. 不要把 WAN 和 LAN 同时接到上游（环路）

### 实测结果（水星 MW325R，原厂固件，1 MB Flash，未刷机）

笔记本连上这台路由器的 WiFi 后：

```
SSID      MERCURY_26A3（802.11n 2.4G）

WLAN  IPv6  2001:250:2003:8f9f:9454:707b:5f12:abec/64     ← 校园网 SLAAC
WLAN  IPv6  2001:250:2003:8f9f:e533:1eb5:3eb8:16cf/128    ← 临时（隐私）地址
WLAN  IPv4  121.48.199.151/24                             ← 上游 DHCP 直接下发

IPv6 默认路由  ::/0 via fe80::7608:aaff:fe99:5c16   (WLAN)
IPv6 前缀路由  2001:250:2003:8f9f::/64              (WLAN)

ping -6 2400:3200::1 → 0% loss, 47 ms
```

**判据**：无线侧 `::/0` 的下一跳 `fe80::7608:aaff:fe99:5c16` 与直插网线时**完全相同** —— 说明路由器是真正的二层透传，没有做路由或 NAT，设备的 IPv6 是端到端的公网地址。

### 顺带发现

同一个墙上网口同时下发了 `121.48.199.149`（有线）和 `121.48.199.151`（无线）两个 IPv4 租约，**"一个网口只给一个地址"的担心不成立**。

### 代价与注意

- **关掉 DHCP 后管理后台够不着**：设备地址是 `121.48.199.x`，路由器在 `192.168.1.1`，不同网段。需要改设置时：电脑接路由器 LAN 口、网卡手动设 `192.168.1.50/24`，再开 `http://192.168.1.1`。所以改之前务必记住 LAN IP。
- 所有设备的 IPv6/IPv4 都是**裸公网地址**，路由器不提供任何防火墙。Windows 网络类别应设为「公用」。
- 无线是 2.4 GHz 单频 802.11n（300 Mbps PHY），实测上限约 90 Mbps，刚好等于百兆网口，不构成额外瓶颈，但抗干扰能力差。
- 回滚：长按 Reset 10 秒恢复出厂。
